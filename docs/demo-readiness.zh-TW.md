# 示範準備度與資料完整性

`npm run demo:check` 在部署前驗證兩份公開快照。精簡版 `dashboard-overview.json` 必須與完整版 `dashboard-snapshot.json` 推導出的內容完全一致，包括產生時間、來源狀態及顯示的觀察資料。完整版須有 schema v4 以上、產生時間、觀察與歷史欄位、方法版本；`trackedTickers` 須為支援 20 標的的非空、不重複子集合。每個啟用 ticker 須至少 60 筆正值、具日期與 HTTPS 來源的收盤價，包含最新應有 NYSE 交易日，最新價格不可超過十天。交易日紐約時間 16:15 起要求當日收盤，其餘時間要求前一交易日，跳過週末及休市日。目前公開快照啟用全部 20 標的：NBIS、CRWV、ORCL、AVGO、APLD、IREN、CIFR、CORZ、GDS、VNET、EQIX、DLR、IRM、VRT、ETN、ANET、PWR、GEV、CEG、BE。

標為 `ok` 的來源不可回報零筆可用資料；事件來源例外，零筆已驗證事件是有效結果。選用來源的降級／部分涵蓋會顯示警示；快照超過 96 小時亦會警示。若存在具日期的事件審查檔案，也須通過範圍、發布日期及 HTTPS 連結檢查。

新版公司訊號只以十筆有來源的收盤價計算 MA5/MA10。基本面、曝險、情緒、可信度及預期差分數，以及推估估值／區域容量，在具備有來源的方法前均無資料。這不影響已揭露的 SEC 財務事實：每家公司都有營收／EPS 研究及可取得的負債／資本支出，附期間、申報、幣別、標籤與分類。五個已審查負債欄位仍明確標示未單獨揭露，缺少欄位不會變成零。舊版 v1 歷史重建不再要求或公布。純價格回測是獨立的回溯分析，不代表可作投資決策。

事件來源有獨立狀態。人工審查檔案可顯示實際 `checkedAt`、審查範圍及 `coverageThrough`；不表示已搜尋所有可能來源。後續較新的自動事件檢查會取代顯示狀態，先前已驗證事件仍保留。

每日發布、PR 驗證及每次 Pages 發布都會執行快照準備度檢查；Pages 也以回歸測試／建置 gate 保護直接推到 `main` 的版本。僅修改文件的 push 跳過發布；僅更新快照的發布跳過 Lighthouse，仍須通過測試與準備度 gate。`npm run verify` 執行本機測試／建置，不連外部來源；`npm run verify:demo` 另外檢查目前公開 artifact。成功 gate 可包含已揭露的事件／公司新聞警示，不表示所有出版來源皆已完整涵蓋或相依套件安全稽核已通過。詳見 [Actions 維運](actions-maintenance.md)及[公司涵蓋](company-research-coverage.md)。
