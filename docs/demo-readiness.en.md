# Demo readiness and data integrity

`npm run demo:check` validates both public snapshot files before deployment. The compact `dashboard-overview.json` must exactly match the runtime projection of the full `dashboard-snapshot.json`, including timestamps, source health and visible observations. The full snapshot requires schema v4 or newer, a generation timestamp, observation/history fields, a methodology version, and a nonempty, unique `trackedTickers` subset of the supported 20-symbol universe. Each enabled ticker needs at least 60 positive, dated, HTTPS-sourced closes through the latest expected NYSE session, with the latest price no more than ten days old. The expected session changes at 4:15 PM New York time on trading days and skips weekends/holidays. All 20 symbols are enabled in the current public snapshot: NBIS, CRWV, ORCL, AVGO, APLD, IREN, CIFR, CORZ, GDS, VNET, EQIX, DLR, IRM, VRT, ETN, ANET, PWR, GEV, CEG and BE.

A source labelled `ok` cannot report zero usable records, except the event source: zero verified events is a valid result. Degraded/partial optional sources are warnings. A snapshot older than 96 hours is flagged. A dated event-review artifact, when present, must also pass its scope, publication-date and HTTPS-link checks.

New company signals are MA5/MA10 calculations over ten cited closes. Fundamental, exposure, emotion, confidence and expectations-gap scores, inferred valuation and regional capacity estimates remain unavailable until a sourced method exists. This does not hide reported SEC financial facts: each company has revenue/EPS research and available debt/capex with period, filing, currency, tag and classification. Five reviewed debt fields remain explicitly not separately reported; no missing field becomes zero. Historical v1 reconstructions are not required or published. The price-only backtest is a separate retrospective analysis and does not make the demo investment-ready.

The event feed has separate status. A curated review file may show a partial check with its actual `checkedAt`, scope, and `coverageThrough`; this is not a claim that every possible event source was searched. Later automated event checks replace the displayed status when newer, while older verified event observations remain available.

Daily publication, PR verification and every Pages publication run snapshot acceptance. Application regression/build checks also gate Pages, including direct `main` pushes. Documentation-only pushes skip publication; snapshot-only publication skips Lighthouse without bypassing tests or acceptance. `npm run verify` runs local tests/build without contacting external providers; `npm run verify:demo` additionally validates the checked-in public artifacts. A successful gate can include disclosed event/news warnings and does not establish full publisher coverage or a passing dependency security audit.
